# rag-knowledge-platform AI 开发工程整体方案

## 目标

- 让 AI 在明确角色、范围和证据要求下参与需求、设计、开发、测试和交付。
- 通过唯一契约减少前后端字段、枚举、分页、权限和错误处理分歧。
- 通过分层规则避免上下文过载，并保护工作区已有改动。

核心原则：

> 统一契约，分别实现；角色明确，边界清晰；AI 执行，人负责决策与验收。

## 统一流程

```text
需求澄清 -> 方案设计 -> API 契约 -> 后端实现 -> 前端实现 -> 测试 -> 发布与复盘
```

每一阶段必须明确输入、负责人、输出、验收条件和未决问题。契约未确认时可以调研和列差异，不应猜测关键字段后直接完成实现。

## 规则体系

1. `AGENTS.md`：轻量入口和红线。
2. `.ai/project.json`：项目结构与验证命令。
3. `.ai/current-role.md`：本地角色和修改边界。
4. `engineering/rules/project.md`：项目规则入口。
5. `engineering/rules/roles/`：角色规则。
6. `engineering/rules/checklists/`：任务清单。
7. `docs/modules/<module>/`：业务事实与唯一契约。

## 角色

| 角色 | 主要职责 | 默认不做 |
| --- | --- | --- |
| 产品/功能负责人 | 目标、范围、规则、优先级、验收 | 直接修改业务实现 |
| 契约负责人 | 唯一 API 契约及变更影响 | 分别维护前后端契约 |
| 前端工程师 | 页面、交互、API client、前端测试 | 私改后端和契约 |
| 后端工程师 | 服务、数据、接口、后端测试 | 私改前端和契约 |
| 测试工程师 | 用例、证据、回归和质量结论 | 用 mock 冒充真实集成 |
| 运维/支持 | 发布、监控、回滚、问题闭环 | 未确认执行高风险操作 |

## 质量与安全

- 开始前查看 Git 状态，保留无关改动。
- SQL、权限、部署、真实数据和外部消息先预览影响与回滚方式。
- 不提交密钥、私网凭据和未脱敏生产数据。
- 交付区分 passed、failed、not-run 和 blocked。
- 构建、静态检查、类型检查、测试和 UI 验证按风险聚焦执行。

## 落地检查

- [ ] 项目结构和验证命令已配置。
- [ ] 每位开发者已建立本地角色。
- [ ] 模块文档和契约负责人明确。
- [ ] 前后端任务引用同一契约版本。
- [ ] 测试、发布、回滚和问题支持有模板与负责人。
