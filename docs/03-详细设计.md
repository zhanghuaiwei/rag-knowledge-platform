## 1. 设计约定

### 1.1 分层

```text
interfaces   HTTP/SSE/webhook/worker entrypoints, DTO mapping, input validation
application  use cases, transactions, authorization orchestration, idempotency
domain       entities, value objects, policies, state machines, ports
adapters     PostgreSQL, Redis, S3, SearchIndex, IdP, connector and model SDKs
```

- Controller/route 不包含业务状态机、权限展开或供应商 SDK 调用。
- domain 不依赖 Spring、FastAPI、OpenSearch/Milvus DSL 或云厂商类型。
- 所有外部调用配置 connect/read/overall timeout、可重试错误、最大尝试、熔断和可观测属性。
- 外部错误转换为内部稳定 reason；公开错误码、HTTP 状态和字段错误由 OpenAPI 冻结。

### 1.2 通用值对象

```java
record TenantId(long value) {}
record UserId(long value) {}
record KnowledgeBaseId(long value) {}
record DocumentId(long value) {}
record DocumentVersionId(long value) {}
record PolicyVersion(long value) {}
record IndexProfileVersion(long value) {}

record PageRequest(int page, int size, List<SortSpec> sort) {
    // page >= 1; 1 <= size <= 100
}
```

- Java/TypeScript JSON 使用 `camelCase`，Python 内部使用 `snake_case` 并由 adapter 映射。
- 时间统一 `Instant`/UTC；金额和费用使用 decimal；checksum 使用 SHA-256 lowercase hex。
- 文件名只作为展示信息，存储 key、解析器选择和权限决策不信任扩展名。

## 2. 身份与租户

### 2.1 身份模型

```java
enum SubjectType { USER, API_KEY, SERVICE }
enum TenantRole { TENANT_ADMIN, SECURITY_ADMIN, KNOWLEDGE_ADMIN, AUDITOR, MEMBER }

record SubjectContext(
    SubjectType subjectType,
    String subjectId,
    TenantId tenantId,
    Set<TenantRole> tenantRoles,
    Set<Long> orgIds,
    Set<String> scopes,
    String credentialId,
    Instant authenticatedAt,
    String traceId
) {}
```

不变量：

- `tenantId/role/org/scope` 只来自验证后的 OIDC session、API Key 记录或 workload identity；忽略客户端自报值。
- `issuer + subject` 唯一映射 `identity_account`；`sys_user` 是全局身份，`tenant_member` 表达租户加入关系。
- 本地账号的 subjectKey 为 `form|<username>`（全局唯一，`user_credential.username` 对应）；OIDC 为 `issuer|subject`。
- 用户可加入多个 tenant 和多个组织；每个请求只激活一个 tenant。
- DISABLED user、tenant membership 或 API Key 在授权缓存 TTL 内必须失效；高风险禁用主动发布 cache invalidation。

### 2.2 OIDC/BFF

```java
interface IdentityProviderPort {
    AuthorizationRedirect beginLogin(String tenantHint, URI returnTo);
    IdentityClaims completeCodeFlow(String code, String state, String nonceVerifier);
    LogoutResult logout(String sessionId);
}

interface IdentityProvisioningService {
    UserIdentity upsertOidcIdentity(String issuer, String subject, UserProfile profile);
    ScimResult applyScimEvent(ScimEvent event, IdempotencyKey key);
}
```

- 使用 Authorization Code + PKCE；校验 state、nonce、issuer、audience、signature、exp/nbf。
- 推荐 BFF 保存加密 session，浏览器只持 Secure/HttpOnly/SameSite cookie；若使用 bearer，禁止 localStorage。
- 平台不接收企业用户密码，不提供 password grant。
- 本地账号场景（form 登录，V0.4）为例外：凭据仅存 `user_credential` 表的 BCrypt hash（见 04-数据库设计），
  登录走 Spring DaoAuthenticationProvider + `UserDetailsService`，仍不提供 password grant / OAuth 密码授权端点；
  该能力面向明确选择本地账号的私有化/自托管部署，企业 IdP 场景继续不接收企业密码。
- SCIM/SAML 属于 adapter；未启用时返回能力不可用，不模拟成功。

### 2.3 租户上下文

```java
interface TenantContextResolver {
    SubjectContext resolve(VerifiedCredential credential, Optional<TenantId> requestedTenant);
}
```

1. 验证 credential。
2. 查询 ACTIVE `tenant_member`；无成员关系返回 forbidden。
3. tenant 切换生成新的 session/access token audience，清理旧 tenant 缓存。
4. 获取 PostgreSQL connection 后执行参数化 `SET LOCAL app.tenant_id = ?`；事务结束自动清理。

## 3. 统一授权设计

### 3.1 权限与角色

```java
enum KbRole { OWNER, EDITOR, VIEWER }
enum Permission {
    KB_MANAGE, MEMBER_MANAGE, DOCUMENT_WRITE, DOCUMENT_REVIEW,
    VIEW_EXCERPT, VIEW_CONTENT, DOWNLOAD_ORIGINAL,
    CHAT, SEARCH, ANALYTICS_READ, AUDIT_READ, API_KEY_MANAGE
}

record ResourceRef(String type, long id, Optional<KnowledgeBaseId> kbId) {}
record AuthorizationDecision(boolean allowed, String reason, PolicyVersion version) {}
```

默认 implication：`DOWNLOAD_ORIGINAL → VIEW_CONTENT → VIEW_EXCERPT`。PDP 负责展开并记录策略版本，调用方不得自行推断。

授权顺序：

1. tenant、subject 和 credential ACTIVE。
2. scope 允许 action/resource type。
3. KB membership/tenant admin policy 允许访问目标 KB。
4. 文档状态满足 action；管理/审核内容也需显式 content permission。
5. 文档有 ACL 时按 allow-list 覆盖 KB 继承；无 ACL 时继承 KB role。
6. classification、有效期、legal hold/retention 和 provider policy 施加附加限制。

平台不支持隐式 deny ACL，避免 allow/deny/继承优先级产生不可解释行为；需要隔离时创建显式 allow-list。

### 3.2 PDP/PEP

```java
interface PolicyDecisionPoint {
    AuthorizationDecision authorize(
        SubjectContext subject, Permission action, ResourceRef resource);

    PolicySnapshotRef compileRetrievalPolicy(
        SubjectContext subject,
        Set<KnowledgeBaseId> kbIds,
        Permission permission);

    Map<DocumentId, AuthorizationDecision> authorizeBatch(
        SubjectContext subject,
        Permission action,
        Collection<DocumentId> documentIds,
        PolicyVersion expectedVersion);
}
```

- 每个 HTTP/worker use case 是 PEP；repository tenant filter 不是业务授权。
- snapshot 由数据库当前 membership/ACL/state 计算，allowed document IDs 存入短期 cache，数据库记录 checksum、版本、主体、动作和过期时间。
- membership、org、KB role、document ACL、review、disabled、current version 或 lifecycle 变化使对应 policyVersion 单调增加并删除旧 snapshot。
- cache 不可用、snapshot 缺失或版本落后时 fail-closed，可回源数据库重算但不可返回全集。

### 3.3 rag-engine 授权上下文

```python
class RetrievalAccessContext(BaseModel):
    snapshot_id: str
    tenant_id: int
    subject_key: str
    permission: Literal["VIEW_EXCERPT", "VIEW_CONTENT"]
    kb_ids: list[int]
    policy_version: int
    issued_at: datetime
    expires_at: datetime
    audience: Literal["rag-engine"]
    jti: str
    signature: str
```

- server 使用专用签名 key 产生短期上下文；rag-engine 验证 audience、签名、有效期、jti 和 workload identity。
- rag-engine 通过受控 PolicySnapshotPort 解析 allowed document IDs；浏览器不能直接调用。
- 检索后、rerank 前批量二次授权；policyVersion 已变化则终止并要求 server 重试一次。
- 不把完整 org/role claim 当长期索引权限真相，避免组织变化后 stale token 放权。

## 4. 知识库与文档

### 4.1 知识库

```java
enum KbStatus { ACTIVE, ARCHIVED, DELETING, DELETED }
enum KbVisibility { PRIVATE, TENANT }

record CreateKnowledgeBaseCommand(
    String name,
    String description,
    KbVisibility visibility,
    long indexProfileId,
    boolean requiresReview,
    Optional<Long> metadataSchemaId,
    Optional<Long> retentionPolicyId
) {}
```

规则：

- 名称在 tenant 的非 DELETED KB 中唯一；名称不是标识，API 使用 id。
- 创建者成为 OWNER；KB 与初始成员在一个本地事务提交并写 outbox。
- ARCHIVED 不接受摄取/同步，按策略可读；DELETING 立即退出搜索/问答。
- clone 是异步任务，复制配置/metadata/ACL 策略；文档默认引用不可变对象版本并重新构建索引，不复制物理向量。

### 4.2 文档与版本

```java
enum DocumentLifecycle { ACTIVE, ARCHIVED, DELETING, DELETED }
enum ReviewStatus { DRAFT, PENDING_REVIEW, PUBLISHED, REJECTED, WITHDRAWN }
enum AuthorityStatus { DRAFT, AUTHORITATIVE, SUPERSEDED }
enum Sensitivity { PUBLIC, INTERNAL, CONFIDENTIAL, RESTRICTED }
enum IngestStatus {
    QUARANTINED, SCANNING, PARSING, CHUNKING, EMBEDDING,
    INDEXING, READY, FAILED, BLOCKED
}
```

- `document` 保存业务身份、所有者、治理与当前版本指针；`document_version` 保存不可变内容事实。
- 更新内容创建新 version；成功发布前旧 current version 继续服务，避免半成品可见。
- `current_version_id` 必须属于同 tenant/document；数据库复合外键兜底。
- 只有 `ACTIVE + PUBLISHED + !disabled + current version READY + valid period` 文档可进入 retrieval snapshot。
- 来源、外部版本、checksum、解析器/profile、处理时间和安全扫描规则版本必须可追溯。

### 4.3 内容访问

```java
interface DocumentContentService {
    ContentExcerpt excerpt(SubjectContext subject, DocumentId id, Location location);
    RenderedPreview preview(SubjectContext subject, DocumentId id, Location location);
    BinaryStream original(SubjectContext subject, DocumentId id, Optional<ByteRange> range);
}
```

- excerpt 要求 `VIEW_EXCERPT`，只返回已净化的短文本和定位。
- preview 要求 `VIEW_CONTENT`，优先返回安全渲染产物；不得通过 preview URL 绕过当前授权。
- original/Range 要求 `DOWNLOAD_ORIGINAL`；Content-Disposition 与 MIME 固定，禁止 inline 执行不安全类型。
- 所有 signed URL TTL 短、绑定 tenant/document/version/permission；生成和使用均审计。

## 5. 内容源与同步

### 5.1 连接器端口

```java
interface ContentConnector {
    ConnectorCapabilities capabilities();
    ConnectionValidation validate(ConnectionConfig config, SecretRef secret);
    DiscoveryPage discover(SyncCursor cursor, int limit);
    SourceContent fetch(SourceObjectRef object);
    SourceAcl fetchAcl(SourceObjectRef object);
    Optional<SyncCursor> nextCursor();
    HealthStatus health();
}

record ConnectorCapabilities(
    boolean delta,
    boolean webhook,
    boolean acl,
    boolean tombstone,
    Set<String> mediaTypes,
    Set<String> regions
) {}
```

- `provider_key` 选择 adapter；凭证只保存 Secret Manager 引用。
- `(tenantId, connectionId, externalId)` 唯一；source version/ETag 未变化时跳过内容下载。
- 源 ACL 映射为 platform principal；无法映射且策略要求权限同步时对象不得发布。
- 源删除/撤权写 tombstone，先从 policy snapshot 移除，再异步处置索引/对象。

### 5.2 同步任务

```java
enum SyncType { FULL, INCREMENTAL, WEBHOOK, RECONCILE }
enum JobStatus { QUEUED, RUNNING, PARTIAL, SUCCEEDED, FAILED, CANCELLED }

interface SyncApplicationService {
    JobId start(long connectionId, SyncType type, IdempotencyKey key);
    void processPage(JobId jobId, SyncCursor cursor);
    void cancel(JobId jobId);
    void replayObject(JobId jobId, String externalId);
}
```

- cursor 只在页面结果成功持久化后推进；429/5xx/timeout 指数退避并遵守 Retry-After。
- 单对象失败不回滚已成功对象，job 返回 PARTIAL 与失败清单。
- reconcile 定期比较源清单与 source_object，发现漏掉的 tombstone/ACL 更新。
- 同步新鲜度以 `last_success_at` 和 oldest pending object 衡量。

## 6. 安全摄取与解析

### 6.1 上传协议

- 小文件直传/大文件 multipart 都以服务端生成 upload ID 管理；client SHA-256 仅作优化，完成后服务端重新计算。
- part size、part count、总大小、文件名、MIME 与 tenant quota 有硬上限。
- complete 使用 Idempotency-Key；相同 upload/source version 只创建一个 document version 和 parse task。
- 对象 key 由服务端生成：`tenant/{tenantId}/kb/{kbId}/document/{documentId}/version/{versionId}/...`，不拼接原文件名。

### 6.2 内容安全端口

```python
class ContentSafetyProvider(Protocol):
    async def scan(self, object_ref: ObjectRef, policy: SafetyPolicy) -> SafetyReport: ...

class SafetyReport(BaseModel):
    status: Literal["PASSED", "BLOCKED", "FAILED"]
    findings: list[Finding]       # redacted; no raw secret in logs
    engine_versions: dict[str, str]
    classification: str | None
```

顺序：真实类型/大小 → archive 层级和解压后大小 → malware/宏/嵌入对象 → DLP/secret → prompt-injection risk。任一 BLOCKED 不进入 parser；扫描服务异常为 FAILED，不按通过处理。

### 6.3 Parser 与统一内容块

```python
class ContentLocation(BaseModel):
    page: int | None = None
    section_path: list[str] = []
    slide: int | None = None
    sheet: str | None = None
    cell_range: str | None = None
    line_start: int | None = None
    line_end: int | None = None

class ContentBlock(BaseModel):
    block_type: Literal["paragraph", "heading", "table", "code", "image_text"]
    text: str
    location: ContentLocation
    metadata: dict[str, str | int | float | bool]

class ParserProvider(Protocol):
    async def parse(self, object_ref: ObjectRef, profile: ParserProfile) -> AsyncIterator[ContentBlock]: ...
```

- PDF/DOCX/PPTX/XLSX/HTML/Markdown/TXT 等 adapter 输出同一 block，不在 domain 判断 SDK 类型。
- OCR 只处理缺失文本层或策略指定页面；输出保留页/区域和置信度。
- Parser/OCR sandbox 禁止默认网络、限制 CPU/内存/文件数/时间；外部 OCR 必须通过数据分类策略。

### 6.4 分块与确定性 ID

```text
chunkId = sha256(documentVersionId + indexProfileVersion + ordinal + normalizedTextHash)
```

- chunker 按 block/标题/表格边界工作，token 限制由 index profile 冻结。
- 相同 version/profile 重放产生相同 chunk ID，SearchIndex upsert 幂等。
- 引用保存 versionId + chunkId + location，不只保存 fileName/page。

## 7. 元数据、审核与生命周期治理

### 7.1 元数据 schema

```java
interface MetadataSchemaService {
    SchemaVersion publishDraft(long schemaId, JsonNode schema);
    ValidationResult validate(long schemaId, int version, JsonNode values);
}
```

- schema 使用受控 JSON Schema 子集：string/number/integer/boolean/date/enum/array；禁止可执行表达式。
- 发布后的 schema version 不可修改；兼容新增字段可创建新版本，必填/类型变化需要迁移计划。
- document_metadata 保存 schemaId/version/values；PUBLISHED 前校验必填、受控词表、owner、classification 和 review date。

### 7.2 审核

```text
DRAFT -> PENDING_REVIEW -> PUBLISHED
              |              |
              v              v
           REJECTED       WITHDRAWN
              |
              +----> PENDING_REVIEW (new or corrected version)
```

- 审核动作绑定 documentVersionId，防止审核 A 版本却发布 B 版本。
- reviewer 不能审核自己提交的高敏内容（四眼原则由 tenant policy 开启）。
- 审核记录追加写，包含 action、comment、actor、policyVersion 和 timestamp。
- 发布只切 current version/状态并写 outbox；索引未就绪时文档保持不可检索。

### 7.3 保留、法律保全与删除

```java
interface DispositionService {
    DeletionPreview preview(SubjectContext subject, DocumentId documentId);
    DeletionTask request(SubjectContext subject, DocumentId documentId, String reason);
    DeletionReceipt execute(TaskId taskId);
}
```

- retention policy 按 tenant/KB/classification 匹配，最严格适用；legal hold 优先级最高。
- 删除预览列出版本、对象、chunks、索引、预览、缓存、会话引用和备份窗口。
- `DELETING` 立即退出授权集合；worker 分目标幂等处置并记录 result/checksum/count。
- down migration、应用回滚或备份恢复不得自动恢复 DELETING/DELETED 内容的在线可见性。

## 8. 索引与检索

### 8.1 IndexProfile

```java
record IndexProfile(
    long id,
    IndexProfileVersion version,
    String embeddingProvider,
    String embeddingModel,
    String modelRevision,
    int dimension,
    String normalization,
    String metric,
    JsonNode chunkerConfig,
    JsonNode analyzerConfig,
    Optional<String> rerankerProvider,
    Optional<String> rerankerModel,
    ProfileStatus status
) {}
```

- ACTIVE profile 不可原地修改；数据库约束范围，application 阻止更新不可变字段。
- KB 引用 profile id；embedding 模型变化必须创建新 profile/build。
- LLM route 不属于 index profile，可独立按请求路由。

### 8.2 SearchIndex mapping

每个 chunk 至少包含：

| 类别 | 字段 |
| --- | --- |
| identity | chunkId, tenantId, kbId, documentId, documentVersionId, ordinal |
| state | lifecycleStatus, reviewStatus, disabled, currentVersion, policyVersion |
| governance | sensitivity, authorityStatus, validFrom/validUntil, ownerId |
| source | sourceType, sourceUpdatedAt, fileExt, language |
| citation | title, sectionPath, page/slide/sheet/cell/line |
| search | text, textAnalyzer, embedding, embeddingDimension, indexProfileVersion |

default OpenSearch adapter：

```text
physical index: ragkb-t{tenantId}-k{kbId}-p{profileVersion}-b{buildId}
read alias:     ragkb-t{tenantId}-k{kbId}-read
```

不把明文 ACL principal 当唯一授权机制；查询必须带 policy snapshot 解析出的 allowed document filter。

### 8.3 IndexBuild 状态机

```text
QUEUED -> BUILDING -> VALIDATING -> READY -> PUBLISHED -> RETIRED
              |            |             |
              +----------> FAILED <------+
```

- BUILDING 写新物理索引；VALIDATING 校验文档/chunk 数、checksum、抽样引用和授权泄漏。
- PUBLISHED 通过单次原子 alias change 完成；同时更新 KB active build 指针。
- 观察期后旧 build 进入 RETIRED；实际删除受保留和回滚窗口控制。
- build/replay 使用 idempotency key，重复事件不创建重复 chunk。

### 8.4 检索 Pipeline

```python
async def retrieve(req: QueryRequest, access: RetrievalAccessContext) -> RetrievalResult:
    verify_access_context(access)
    allowed_ids = await policy_snapshot_port.resolve(access.snapshot_id)
    if not allowed_ids:
        return RetrievalResult.empty()

    filters = {
        "tenantId": access.tenant_id,
        "kbId": {"in": access.kb_ids},
        "documentId": {"in": allowed_ids},
        "currentVersion": True,
        "lifecycleStatus": "ACTIVE",
        "reviewStatus": "PUBLISHED",
        "disabled": False,
    }
    lexical, vector = await search_index.hybrid(req.query, filters, recall_each=40)
    fused = rrf(lexical, vector, k=60)
    authorized = await policy_port.authorize_candidates(fused, access.policy_version)
    ranked = await reranker.rerank(req.query, authorized[:40], top_n=10)
    return select_with_threshold(ranked, req.top_k)
```

- 过滤必须在召回前生效；post-filter 只能做额外展示过滤，不能承担权限。
- `allowed_ids` 过大时 adapter 使用 server-side policy set/terms lookup，不截断；任何性能降级不能改变授权语义。
- 搜索深分页使用 PIT/search_after；公开 API 是否暴露 cursor 由契约评审决定。
- 高亮在 escaped text 上生成结构化 ranges；不得直接返回拼接的未净化 `<mark>` HTML。

### 8.5 Embedding 与模型路由

```java
interface ProviderPolicyService {
    ProviderRoute select(
        TenantId tenant,
        String capability,
        Sensitivity sensitivity,
        String dataRegion,
        String purpose,
        BudgetContext budget);
}
```

- embedding route 由 index profile 固定；不可按月调用量自动切换。
- reranker/LLM/OCR 可在 policy 允许集合内动态路由；fallback 仍校验 sensitivity/region/purpose。
- **`dataRegion` 解析（C7 决策，冻结）**：顺序为 `document.data_region ?? kb.data_region ?? tenant.data_region`；KB 区域在创建时继承租户落库，文档级仅在驻留差异时覆盖。任何 provider 选择都不得让高敏内容越过其区域允许集。
- 记录 provider/model/revision、input/output token、latency、cost、route reason 和 error；不记录原文 prompt。
- timeout/429/5xx 可重试或 fallback 一次；内容安全、授权、4xx 参数和 policy 拒绝不可重试为其他 provider。

## 9. 对话、引用与输出安全

### 9.1 会话

- chat_session 属于 tenant/user；KB 选择使用 `chat_session_kb` 关系而非 JSONB，保证归属与权限可验证。
- 每次提问重新授权 KB；历史会话不能固化旧 membership。
- memory 默认最近 N 轮 + 可配置摘要；历史内容同样视为不可信用户数据。

### 9.2 生成上下文

```text
SYSTEM_POLICY(versioned)
USER_QUESTION(untrusted)
AUTHORIZED_CONTEXT[
  {sourceId, documentVersionId, location, text(untrusted)}
]
OUTPUT_SCHEMA(answer, citations, confidence, refusalReason)
```

- 文档中的“忽略以上指令”“调用 URL”“显示其他文档”等内容不会进入 system role。
- 模型无工具、数据库或任意网络能力；未来 agent/tool 必须单独威胁建模与授权。
- no-answer 判定组合检索阈值、引用覆盖和业务域校准；拒答模板不宣称事实。

### 9.3 SSE

事件顺序保持 `meta → token* → sources? → final` 或 `meta → error`：

- meta：request/session/message、model route、prompt/index/policy version。
- token：单调 seq 和纯文本片段。
- sources：仅含本次最终授权候选的 documentVersion/location。
- final：answer status、confidence、citations、usage/cost 和 output safety result。
- error：稳定 code、requestId、retryable；不暴露 provider 原始响应或敏感内容。

断连：取消下游生成；已生成 token 可记录为 `CANCELLED` 技术事件，但不保存为完整 assistant answer。SSE 重连是否重放由 OpenAPI 明确，不以重复模型调用模拟恢复。

### 9.4 引用

- `chat_message_source` 规范化保存 message/document/version/chunk/location/rank/score/textHash。
- 引用点击先按当前 SubjectContext 重新 authorize，再返回 excerpt/preview；撤权后显示“来源不可再访问”，不泄漏标题/摘要。
- 文档更新不会篡改历史 source version；UI 可提示“已有新版本”。

## 10. API Key、Webhook 与外部集成

### 10.1 API Key

- 生成至少 256 bit 随机 key；只返回一次明文；数据库保存 HMAC-SHA-256/peppered digest 与 prefix。
- key 绑定 tenant、scopes、allowed KB、rate limit、expiresAt；记录 lastUsedAt、revokedAt、createdBy。
- scope 示例：`search:read`、`chat:invoke`、`document:read`；管理 API 不接受普通调用 key。
- credential 泄漏处理为 revoke + audit；轮换允许短期双 key，不改变主体权限。

### 10.2 Webhook

- 订阅只保存 `secret_ref`；payload 含 eventId/type/version/occurredAt/tenant/resource，使用 HMAC 签名和 timestamp 防重放。
- URL 经过 SSRF 防护；响应 body 丢弃或限长摘要，禁止写完整敏感内容。
- delivery 状态 `PENDING/SENDING/SUCCEEDED/RETRY/DEAD`，指数退避 + jitter；事件和投递幂等。

## 11. 事务、事件与并发

### 11.1 事务边界

| Use case | PostgreSQL 本地事务 | 事务外副作用 |
| --- | --- | --- |
| 创建 KB | kb + owner member + outbox | 初始化索引/默认策略 |
| 完成上传/同步 | source/version/task + outbox | 对象写入、扫描、解析 |
| 发布版本 | review + document pointer/state + policy version + outbox | index upsert/alias |
| ACL/成员变更 | ACL/member + policy version + outbox | snapshot/cache invalidation |
| 删除请求 | deletion state/task + outbox | object/index/cache 处置 |

禁止在数据库事务内等待模型生成、批量解析、完整对象上传或 SearchIndex build。

### 11.2 Outbox

```java
record OutboxEvent(
    long id,
    UUID eventId,
    TenantId tenantId,
    String aggregateType,
    String aggregateId,
    long aggregateVersion,
    String eventType,
    String topic,          // 路由键：sync / ingestion / index / webhook / governance / general
    JsonNode payload,
    Instant occurredAt
) {}
```

- 同一 aggregate 按 version 有序处理；跨 aggregate 不承诺全局顺序。
- dispatcher 使用 `FOR UPDATE SKIP LOCKED` 抢占；发布成功后更新状态。
- consumer 保存幂等结果或使用确定性 upsert；重复事件不得重复计费、建版本或发 Webhook。
- payload 只含引用/必要状态，不包含原文、token 或 secret。

**Worker 路由（C1 决策，冻结）**：

- 每个事件带 `topic` 路由键，取值 `sync`（连接器同步）、`ingestion`（安全扫描/解析/OCR/分块/embedding）、`index`（索引构建/发布）、`webhook`（Webhook 投递）、`governance`（策略版本/删除/保留/保全传播）、`general`（缓存失效等通知）。
- 每类 worker 只抢占自己 topic 的事件：`FOR UPDATE SKIP LOCKED WHERE topic = ? AND status = 'NEW'`，互不干扰，可独立扩缩容（对齐 06-架构 §1.1 部署单元）。
- 重计算类事件：consumer 以 `idempotencyKey` 在对应任务表（`parse_task` / `sync_job` / `index_build`）upsert 任务行，再按任务状态机 + 租约（`worker_id`/`lease_until`）执行；outbox 事件仅承担通知与幂等键，不做任务真相。
- 纯通知类事件（如策略版本增长后的缓存失效、RLS/ACL 传播）：由对应 worker 直接消费，不落任务表。
- 死信：`attempt_count` 超限 → `DEAD` + `dead_letter_at` + `last_error_code`；以"最老事件年龄"告警（06-架构 §6.3），由治理/运维确认后人工重放或修复。

### 11.3 乐观锁与幂等

- document、KB、connection、policy 等可变聚合包含 `row_version`；更新 `WHERE id AND row_version`，冲突返回 reload/retry。
- 所有异步 command 与危险写入接受 Idempotency-Key，数据库唯一 `(tenant_id, operation, key)` 或 task key。
- ACL、review、alias switch 使用 compare-and-set expected policy/build version，避免旧任务覆盖新状态。

## 12. 缓存设计

| Key | 内容 | TTL/失效 |
| --- | --- | --- |
| `tenant-membership:{user}` | ACTIVE tenant memberships | 短 TTL；SCIM/禁用主动失效 |
| `policy-version:{tenant}:{kb}` | 当前策略版本 | 长 TTL + 事件更新；缺失回源 |
| `policy-snapshot:{id}` | allowed doc set/compiled filter | ≤60s；任何相关策略变化删除 |
| `provider-health:{provider}` | capability/health | 15–30s；不覆盖合规 policy |
| `rate:{tenant}:{credential}:{route}` | 滑动窗口 | 与窗口一致 |
| `task-lock:{operation}:{resource}` | 短期互斥 | lease + fencing token |

Redis 丢失只导致重算/限流保守，不丢业务事实；授权 snapshot 解析失败不返回全量结果。

## 13. 数据库与仓储规则

- Repository 方法必须接收 TenantId 或由 transaction-bound context 提供；禁止无范围的 `findById(id)` 访问租户资源。
- 所有跨租户父子关系由复合 FK 保证；应用还要验证业务权限。
- 关键 enum/range/time 由 CHECK 兜底；JSONB 必须有 schema version 和应用校验。
- 审计、review、outbox、delivery/source history 追加写；普通 runtime role 不获得 TRUNCATE/DDL。
- 数据库 schema 由 Flyway/migration job 管理；新装 DDL 见 `deploy/ddl/init.sql`，v0.1 expand migration 策略见 `04-数据库设计.md` §9.2。

## 14. 错误与重试分类

| 类别 | 例子 | 是否重试 | 对外语义 |
| --- | --- | --- | --- |
| VALIDATION | 字段/格式/状态不合法 | 否 | 400 + field details |
| UNAUTHENTICATED | token/service identity 无效 | 重新认证 | 401 |
| FORBIDDEN | tenant/scope/ACL/classification | 否 | 403 或防枚举 404 |
| CONFLICT | rowVersion、状态机、幂等 payload 不同 | reload/有限重试 | 409 |
| QUOTA | 大小、QPS、token、storage | 按窗口 | 413/429 |
| SAFETY_BLOCKED | malware/DLP/policy | 否 | 422/受控业务错误 |
| DEPENDENCY_TRANSIENT | timeout/429/5xx | 退避/合规 fallback | 503 + retryable |
| DEPENDENCY_PERMANENT | 4xx config/provider capability | 否，人工处理 | 422/503 |
| INTERNAL | 未分类异常 | 仅幂等任务可重试 | 500 + requestId |

公开 `code` 必须在 OpenAPI 中唯一维护；日志保存内部 reason、dependency 和 retry decision，但不回传堆栈/secret。
