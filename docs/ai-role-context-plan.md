# AI 开发角色上下文方案

## 背景

分支名无法可靠表达当前开发者是产品、契约、前端、后端、测试还是全栈角色。使用本地角色文件，可以让 AI 在修改前明确允许、确认和禁止范围。

## 文件

```text
.ai/
├─ project.json                 # 可提交的项目配置
├─ current-role.example.md      # 可提交的角色模板
└─ current-role.md              # 本地角色，不提交
```

## 使用

1. 复制 `current-role.example.md` 为 `current-role.md`。
2. 填写角色、人员、模块、阶段和路径边界。
3. 使用目标项目已有忽略规则排除 `current-role.md`。
4. AI 开始开发前读取该文件；角色或阶段变化时及时更新。

## 判断规则

- 允许路径：可在任务范围内直接修改。
- 确认路径：先说明影响并获得确认。
- 禁止路径：不直接修改，除非用户明确切换角色或授权。
- 角色边界优先于一般任务清单；安全和真实外部影响仍需单独确认。
