# 前后端 AI 协作开发流程

核心原则：

> 前端和后端可以分别生成代码，但不能分别定义接口。

## 协作流程

1. 产品/功能负责人收口目标、范围、业务规则和验收标准。
2. 契约负责人维护一份 API 契约，前后端共同评审。
3. 前后端任务分别拆分，引用同一契约路径、版本和状态。
4. 后端完成接口与聚焦测试，记录可联调条件。
5. 前端基于契约实现 API client、类型、页面和交互状态。
6. 双方对账路径、字段、枚举、分页、权限和错误处理。
7. 测试覆盖主流程、异常、权限、边界和回归，形成交付记录。

## 变更处理

发现契约缺口时，不在代码中各自绕过：

1. 提交变更原因和影响范围。
2. 契约负责人更新版本与变更记录。
3. 前端、后端、测试和发布任务同步调整。
4. 破坏性变更补充兼容、迁移或回滚方案。

## 联调清单

- [ ] 请求路径、方法、认证和权限一致。
- [ ] 字段、类型、必填、空值和默认值一致。
- [ ] 枚举、状态流转、分页和排序一致。
- [ ] 错误码、提示和异常示例一致。
- [ ] Mock 已替换或明确隔离，不作为真实联调证据。
