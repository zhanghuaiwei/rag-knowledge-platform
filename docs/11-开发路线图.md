## 0. 分工与节奏

- **后端（service/）业务逻辑由人工实现**：AI 只维护接口入口骨架（Controller、DTO、错误码、Service 接口契约）；未实现方法统一抛 `NotYetImplemented.stub(...)` → 501 `E-9998`。人工替换实现点即可，**无需改动 Controller 与契约**。
- **前端（web/）真实 API 对接由 AI 完成**：`web/src/api/` 双 transport（mock/http）由 `NEXT_PUBLIC_USE_MOCK` 切换。
- **rag-engine（Python）对接**：AI 预留 `RagEnginePort` + `RagEngineHttpClient` 桩，HTTP/SSE 对接由人工实现。
- 状态图例：`✅ 已完成` ｜ `🔜 下一步（详细展开）` ｜ `⏳ 待推进（占位）`。
- 每步是**一个可独立验收的增量**；改契约先改 OpenAPI 再同步前后端与测试。

### 2.4 技术点

- **单一契约 + 类型生成**：OpenAPI YAML 是唯一权威；`docs/07-API契约.md` 摘要由机器生成或 CI 对账，杜绝人工摘要漂移（P0-4）。
- **数据库迁移**：DDL 为一次性脚本按序执行，区分「建库/迁移」权限；回滚需单独增量脚本；凭证一律 `RAGKB_DB_*` 环境变量。
- **MyBatis-Plus**：分页插件（`PageRequest → PageData`，jsqlparser）、多租户插件（`ignoreTable` 白名单防多表 JOIN 冲突）、乐观锁 `@Version`、`id-type: auto`（BIGINT identity）。
- **Spring Security**：form 模式（开发）登录 → `SecurityContext` → 解析为 `SubjectContext`（tenant/role）；OIDC 模式开关保留，不暴露表单登录。
- **事务边界**：写操作在 Service 层 `@Transactional`，业务异常与系统异常分开；幂等键预留（后续 Redis）。
- **统一响应**：`{ code, message, data }` + `requestId` 链路；分页统一 `page/pageSize + total/list`。
- **前端双 transport**：`mock/http` 由环境变量切换；axios 拦截器统一带鉴权头、401 刷新/跳登录、错误按 `code` 差异化处理。

### 2.5 可能的扩展（本步加分项 / 后续入口）

- **RLS 纵深防御**：应用先设置 tenant context，再按 `deploy/ddl/init.sql` 附录 A 启用（P0-5 收口）。
- **契约 CI 对账**：`.github/workflows` 加 OpenAPI → 07 摘要一致性校验，契约未冻结即阻断合并。
- **本地 OIDC 验证**：Keycloak（compose）起真 IdP，验证 `ragkb.auth.mode=oidc` 链路。
- **KB 自动化测试**：Service 层单测 + `Testcontainers`(PG) 集成测试，覆盖分页/租户过滤/权限。
- **审计埋点**：`@AuditLog` AOP 提前接入，S1 即开始追加写审计留痕。
- **对象存储前置**：`ObjectStorePort`（MinIO 适配）提前接通，为 S2 上传/分片铺路。
- **上传/分片**：S2 的文档上传先行落地，KB 切片验收时可直接验证「建库 → 传文档 → 列表可见」。

## 3. 后续步骤（占位，推进时逐个展开）

> 以下为路线骨架；进入某步时，把该步的 **开发任务 / 技术点 / 可能的扩展** 补充完整。

### S2 文档全生命周期
- **目标**：上传 → 对象存储 → 分片/合并 → 解析状态机（先接 mock rag-engine）→ 不可变版本。
- **前置**：S1 的 ObjectStorePort；`DocumentController/DocumentService` 已就绪。
- **关键决策**：分片阈值、状态机流转、版本指针切换、大文件 OOM 防护。

### S3 检索与可信问答
- **目标**：`RagEnginePort` 真实对接（ingest/query/delete/task，内网 `http://rag-engine.ragkb.svc:8000`）；混合检索 + RRF + 精排；SSE 流式问答 + 引用；前端 `/chat`、`/search` 页。
- **关键决策**：内部检索授权上下文（P0-1）、索引字段与策略版本（P0-2）、SSE 断线重连与幂等。

### S4 身份与权限闭环
- **目标**：OIDC Authorization Code + PKCE 真 IdP；scoped API Key；文档级 ACL allow-list；检索授权上下文签名。
- **关键决策**：ACL 判定与缓存失效、fail-closed、`view_excerpt/view_content/download_original` 分离。

### S5 企业治理与开放能力
- **目标**：ContentConnector 首批（文件/对象存储 + 1 个企业源）、内容审核状态机、组织部门树、Webhook 推送、审计查询。
- **关键决策**：连接器增量游标与幂等、审核队列、Webhook 签名与重试。

### S6 可靠性、质量与交付强化
- **目标**：SLO/RPO-RTO、Prometheus/Grafana 监控告警、E2E 关键路径、RAGAS 黄金集评测、部署（compose → K8s）。
- **关键决策**：指标口径、评测门禁进 CI、备份恢复演练。

## 4. 变更流程

1. 调整范围/排期 → 更新 §1 总览与本文件对应步骤。
2. 契约变更 → 先改 `docs/api/*.openapi.yaml` 并标记版本，再同步前端类型、07 摘要与受影响步骤。
3. 每完成一个步骤 → 该步验收打勾、状态改 `✅`，并详细展开下一「下一步」。
