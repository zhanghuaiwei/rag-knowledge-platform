# AI 全栈协作文档结构方案

## 目标

业务按模块聚合，接口契约唯一，前后端任务分离，AI 基于同一事实源工作。

## 推荐结构

```text
docs/modules/<module>/
├─ requirements/       # 目标、范围、规则、验收
├─ design/             # 流程、模型、交互、技术方案
├─ api/                # 唯一 API 契约
├─ tasks/
│  ├─ frontend/        # 前端可执行任务
│  └─ backend/         # 后端可执行任务
├─ test/               # 测试计划、用例和结果
├─ ops/                # 发布、配置、监控和回滚
└─ support/            # 问题复现、归因和闭环
```

## 文档职责

- 需求回答“为什么、做什么、如何验收”。
- 设计回答“流程、边界和方案如何组织”。
- API 回答“前后端共同遵循什么协议”。
- 任务回答“由谁在哪些文件完成什么并如何验证”。
- 测试和运维记录真实执行证据，不复制计划充当结果。

## 版本与变更

- 契约标明状态和版本。
- 任务引用契约路径与版本。
- 字段、枚举、路径、错误码和权限变更记录原因、兼容和影响范围。
- 过期文档归档或明确标记，避免多个“最终版”。
