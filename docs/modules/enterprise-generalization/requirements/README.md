# 通用企业知识库需求与差距分析

> **文档状态**：评审中 · **版本**：v0.2-draft · **负责人**：待指定 · **最近更新**：2026-08-10
> **现有权威源**：功能与验收见 [`../../../01-需求分析.md`](../../../01-需求分析.md)，接口见 [`../../../07-API契约.md`](../../../07-API契约.md) 与 `docs/api/*.openapi.yaml`，数据见 [`../../../04-数据库设计.md`](../../../04-数据库设计.md)。

## 1. 审计结论

**结论：部分遵循，但尚未达到可交付的通用企业知识库标准。**

现有设计已经覆盖多知识库、文档解析、混合检索、引用问答、多租户、组织角色、文档 ACL、审核、审计、RAG 评测和容器化运维，属于方向正确的“企业级 RAG 方案草稿”。但当前还存在三类本质差距：

1. `web/` 产品化页面 + mock/http 双 transport 已实现（可运行演示），`service/` 为完整接口入口骨架（Controller/DTO/错误码 + Spring Security form/OIDC + MyBatis-Plus 骨架，业务用例仍为 `NotYetImplemented` stub），`rag-engine/` 为探针骨架；构建/测试命令均已配置。业务能力交付成熟度仍不能高于“接口骨架 + mock 演示”，真实数据链路待 service 业务用例人工实现。
2. 权限、OAuth、OpenAPI 与检索索引之间存在阻断性矛盾，按当前契约实现会产生越权或无法实现的行为。
3. 主要摄取入口仍是手工上传/ZIP，缺少连接器、增量同步、源权限传播、元数据模型、内容安全和企业治理，因此难以适配不同组织与行业。

### 1.1 能力判定

| 维度 | 当前判定 | 主要证据 | 达标条件 |
| --- | --- | --- | --- |
| 知识摄取 | 部分满足 | 多格式、分片、OCR、版本和 ZIP 已设计 | 有标准连接器、增量同步、删除传播、去重、来源血缘和失败恢复 |
| 检索与问答 | 部分满足 | 混合检索、RRF、精排、引用和拒答已设计 | 授权过滤贯穿问答/搜索、索引字段可支撑过滤、质量按场景持续评估 |
| 身份与权限 | 不满足 | 有租户/组织/KB 角色/文档 ACL 概念 | 改用 OIDC 标准流；ACL fail-closed；服务身份认证；数据库防跨租户约束 |
| 内容治理 | 部分满足 | 有审核、审计和简单保留期 | 有所有者、分类分级、保留/法律保全、过期复审、可证明删除和策略版本 |
| 安全合规 | 不满足 | 有 TLS、Secret、日志脱敏和基本上传校验 | 有恶意文件隔离、DLP、间接提示词注入防护、输出防泄漏、密钥/数据驻留策略 |
| 开放与通用 | 部分满足 | LLM/OCR 有局部 provider 思路 | 存储、解析、检索、身份、模型和事件均端口化；供应商配置不进入领域语义 |
| 可靠性运维 | 部分满足 | 有探针、监控、备份与回滚描述 | 明确 SLO、RPO/RTO、容量配额、恢复演练证据和不可变版本基线 |
| 工程交付 | 不满足 | OpenAPI 可解析，但摘要与机读契约不同步 | 代码可构建、契约完整、生成客户端一致、迁移可回滚、自动化测试有执行证据 |

### 1.2 已有设计中值得保留的模式

- 文档解析与审核状态分离，便于把“技术就绪”和“业务可发布”分别治理。
- 混合检索、精排、引用和低置信拒答组成了可信问答的正确骨架。
- 多租户、知识库成员和文档 ACL 分层，适合继续演进为统一策略决策。
- OpenAPI、RAG 评测、结构化日志、备份恢复和成本统计已经有明确入口。

### 1.3 对照基线

- [RFC 9700: Best Current Practice for OAuth 2.0 Security](https://www.rfc-editor.org/rfc/rfc9700.html)：浏览器和机器身份、token 最小权限与密码 grant 基线。
- [NIST SP 800-207: Zero Trust Architecture](https://csrc.nist.gov/pubs/sp/800/207/final) 与 [SP 800-207A](https://csrc.nist.gov/pubs/sp/800/207/a/final)：不因网络位置隐式信任服务，按身份与资源执行策略。
- [NIST AI 600-1: Generative AI Profile](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-generative-artificial-intelligence)：数据保护、保留、来源、监控、评测和第三方模型风险。
- [OWASP Top 10 for LLM Applications 2025](https://genai.owasp.org/llm-top-10/)：提示词注入、敏感信息泄漏、数据投毒、输出处理、向量/embedding 和资源消耗风险。

## 2. 阻断问题

### P0-1 问答 ACL 没有进入内部检索契约

- 需求要求文档 ACL 同时约束搜索、预览和问答，但 `QueryChatRequest` 没有 `tenantId`、授权策略版本或可见文档过滤条件。
- QueryPipeline 只描述 `tenant_id + kb_id` 过滤；搜索有 `docIdWhitelist`，问答没有同等约束。
- **影响**：被单文档 ACL 排除的内容仍可能被召回并进入模型上下文，造成敏感信息泄漏。
- **必须修复**：server 在每次检索前完成主体、租户、知识库、文档策略判定；将不可省略的授权上下文传给 rag-engine；rag-engine 对缺失、过期或空授权上下文 fail-closed，并在生成前对候选文档二次校验。

### P0-2 索引模型无法执行已声明的业务过滤

- 需求要求按 `review_status`、`is_disabled`、文件类型、时间、当前版本和 ACL 过滤。
- Milvus 设计字段没有 `review_status`、`is_disabled`、`file_ext`、`created_at` 或策略版本；搜索流程却直接使用这些条件。
- **影响**：未发布、已禁用或旧版本内容可能参与检索，部分搜索条件无法实现。
- **必须修复**：冻结统一的索引文档元数据；发布/禁用/ACL/版本变化必须生成可重放索引事件；查询使用同一策略版本，状态更新失败时默认不返回文档。

### P0-3 OAuth 密码模式不适合作为企业登录基线

- 当前设计由前端收集账号密码并使用 Resource Owner Password Credentials grant。
- OAuth 2.0 Security Best Current Practice（RFC 9700）明确禁止使用该模式；该模式也不能正常承载 MFA 和企业身份提供商交互。
- **必须修复**：浏览器登录改为 OIDC Authorization Code + PKCE；服务集成使用 client credentials 或受约束 API Key；token 校验加入 `iss/aud/exp/nbf/jti`，refresh token 继续轮换并检测重放。

### P0-4 人工 API 摘要与机器契约冲突

- `docs/07-API契约.md` 声明 OpenAPI YAML 是最终契约，但前端到 server 的摘要包含 49 个唯一资源路径，YAML 只有 22 个路径，其中至少 27 个摘要路径不存在于 YAML。
- 缺失覆盖成员、版本、ACL、用户、审计、Webhook、SSO、收藏、部分统计和 token revoke 等核心能力。
- **必须修复**：只保留机读契约为权威源；摘要由契约生成或由 CI 对账；所有路径必须定义权限、请求/响应、错误、幂等和分页，再生成前后端类型。

### P0-5 多租户完整性只依赖应用过滤

- 多数含 `tenant_id` 的表没有到租户的外键，也不能约束关联资源属于同一租户；`sys_user` 又被租户插件豁免。
- 多个角色、状态和参数字段没有数据库 CHECK；组织根节点用 `parent_id=0`，不能由外键保证组织树完整性。
- **影响**：错误写入、批处理、管理接口或未来绕过 ORM 的查询可形成跨租户关系。
- **必须修复**：明确“用户是全局身份还是租户身份”；对租户内关系使用复合唯一键/复合外键或等价约束；关键枚举和范围加约束；评估 PostgreSQL RLS 作为纵深防御。

### P0-6 Embedding 自动换模缺少可迁移索引配置

- 设计允许同一知识库在 1024 维和 3072 维 embedding 间按用量切换，但没有冻结 collection、索引配置版本、重嵌入任务和原子切换流程。
- **影响**：查询向量与存量向量维度或语义空间不一致，导致请求失败或检索质量不可控。
- **必须修复**：知识库绑定不可变 `indexProfileVersion`；换模只通过“新索引全量重建 → 质量校验 → 别名原子切换 → 旧索引延迟回收”完成，不能按请求或用量直接切换 embedding。

## 3. 通用化增量需求

### GKB-01 统一授权闭环（P0）

- 浏览器、API Key 和服务身份统一映射为 Subject；每次请求解析 tenant、subject、scope、允许的知识库/文档和 policyVersion。
- 搜索、问答、引用、预览、下载、导出、统计和管理接口都调用同一策略决策点，默认拒绝。
- ACL 变更、组织变更、成员变更和文档状态变更立即使缓存失效并产生索引策略更新事件。
- `view_excerpt`、`view_content`、`download_original` 明确分离；返回原始文件流的接口必须要求 `download_original`，不能以 UI 禁止下载代替权限。

**验收**：被排除用户无法从搜索结果、答案文本、引用元数据、预览流、下载流、导出、缓存或历史会话获取该文档；缺失授权上下文时 rag-engine 返回拒绝而不是宽松检索。

### GKB-02 企业身份与机器访问（P0）

- 支持 OIDC Authorization Code + PKCE，MFA 由企业 IdP 承载；保留可插拔 SAML 适配入口。
- 用户与租户成员关系分离，支持一人多租户、多部门/用户组、嵌套组和停用同步；P1 接入 SCIM 2.0 生命周期同步。
- API Key 必须有 scope、允许知识库、有效期、创建者、最近使用、吊销时间和密钥版本；高熵 key 使用带服务端 pepper 的不可逆摘要。
- server ↔ rag-engine 使用工作负载身份 + mTLS 或等价短期凭证，不因“集群内网”而跳过认证。

**验收**：密码 grant 不再暴露；禁用 IdP 用户/SCIM 成员后在目标 SLA 内失去访问；机器凭证无法访问未授权知识库；内部伪造请求被拒绝。

### GKB-03 内容源连接器与同步（P1）

- 定义 `ContentConnector` 能力：授权、发现、拉取、增量游标、Webhook、ACL 映射、限流、重试、删除墓碑和健康检查。
- 第一批适配文件上传、对象存储/网络盘、SharePoint/OneDrive、Confluence、企业网页；其他来源按同一端口扩展。
- 每个来源记录外部 ID、版本/ETag、来源 URL、采集时间、内容指纹、ACL 快照、同步游标和删除状态。
- 同步必须幂等；源删除/撤权在 SLA 内传播到检索索引；失败进入可重放队列并可按单文档重试。

**验收**：同一对象重复同步不产生重复文档；增量更新只重建受影响版本；源撤权/删除后在约定时间内不可搜索、不可问答、不可预览。

### GKB-04 通用元数据与知识治理（P1）

- 支持租户级元数据 schema、字段类型、必填规则、受控词表、分类层级、内容所有者和业务域。
- 文档具备来源血缘、语言、敏感级别、有效期、复审日期、权威状态和替代文档关系。
- 保留策略按租户/知识库/分类配置，支持法律保全、审批删除、对象/索引/缓存/备份的删除传播和删除证明。
- 审计记录采用追加写语义，记录策略版本和前后状态；导出遵循最小权限和脱敏策略。

**验收**：必填元数据不满足时不得发布；过期内容可自动下线或进入复审；法律保全对象不能被清理；删除任务可证明所有在线副本均已处置。

### GKB-05 内容与生成式 AI 安全（P0/P1）

- 上传先进入隔离区，执行真实类型识别、压缩炸弹限制、恶意软件扫描和宏/脚本处置，再进入解析。
- 对输入文档、用户问题、模型上下文和输出分别实施 DLP/PII/密钥检测；外部模型路由受数据分类和数据驻留策略约束。
- 文档内容始终视为不可信数据，防护间接提示词注入、数据投毒和向量/embedding 攻击；模型不得把检索内容当作系统指令。
- 输出引用只能指向本次授权候选；HTML/Markdown/链接均按上下文净化，禁止模型输出触发未授权外部动作。
- 建立 AI 安全红队集和安全事件响应：提示词注入、敏感信息泄漏、错误引用、拒答绕过、资源耗尽。

**验收**：恶意文件不离开隔离区；含“忽略系统指令”的文档不能改变系统策略；高敏内容不会路由到不允许的外部模型；模型输出不能生成可执行 XSS 或越权引用。

### GKB-06 检索质量、可解释性与新鲜度（P1）

- 黄金数据集按租户、业务域、语言、权限角色和时间敏感性分层，避免单一全局阈值掩盖弱场景。
- 除 RAGAS 外记录 Recall@K、MRR/nDCG、引用正确率、拒答准确率、ACL 泄漏率、延迟和成本。
- 答案携带内容版本、来源、页/段、检索时间和“信息可能过期”提示；删除或撤权后历史引用不可继续打开。
- 配置变更、换模、分块策略和 reranker 变更先离线评估，再小流量发布并可回滚。

**验收**：每次索引配置发布有对比基线；引用必须定位到当前可见版本；关键业务域质量退化会阻断发布。

### GKB-07 可移植扩展与供应商治理（P1）

- 领域层仅依赖解析、OCR、embedding、向量索引、关键词索引、rerank、LLM、对象存储、身份和事件端口。
- 阿里云 OCR、Ollama、Milvus、MinIO 等均为适配器；租户可通过策略选择本地/云服务，但不能绕过安全和数据驻留约束。
- 第三方模型/连接器记录版本、区域、数据用途、SLA、限额和退出方案；镜像和依赖使用固定版本并纳入 SBOM/漏洞扫描。

**验收**：替换同类 provider 不修改领域用例；provider 故障有受控降级；外部供应商停用后可导出并重建核心数据。

### GKB-08 可运营与可靠性（P1）

- 定义按租户配额：存储、文档数、同步吞吐、查询并发、token、导出和连接器调用。
- 为登录、上传、同步、检索、问答、ACL 传播和删除传播定义 SLI/SLO；日志、指标和 trace 使用同一 requestId/traceId。
- 定义分层备份、跨故障域恢复、RPO/RTO 和季度恢复演练；Milvus 可由对象与元数据事件重建。
- Webhook 禁止内网/元数据地址，使用 egress allowlist、DNS/IP 复核、签名轮换、投递日志、重试退避和死信队列。

**验收**：容量超限行为可预测；恢复演练在 RPO/RTO 内完成；Webhook SSRF 测试通过；关键异步任务可重放且不重复生效。

## 4. 分期与非目标

### 推荐分期

1. **Gate 0——先消除阻断项**：统一授权上下文、索引字段、OAuth/OIDC、OpenAPI 对账、多租户完整性、embedding 迁移策略。
2. **企业 MVP**：安全上传、元数据/所有者/新鲜度、API Key scope、服务身份、基础 SLO 与可执行测试。
3. **通用化扩展**：连接器 SDK、增量/ACL 同步、SCIM、保留与法律保全、供应商策略。
4. **生产强化**：红队、数据驻留、多区域灾备、配额计费、插件生态和行业模板。

### 本轮不做

- 不直接修改公共 OpenAPI 或真实部署配置；v0.2 DDL 已作为设计基线补齐，但未连接/修改真实数据库，生产执行仍需数据与运维评审。
- 不把计划中的连接器、SSO、ACL 或测试描述为已实现。
- 不把某个供应商产品写进领域契约，也不为尚未确认的行业预置固定字段。

## 5. 已冻结设计默认值与待定业务参数

本次设计已冻结：SaaS/私有化共用领域模型、全局用户 + 租户成员 + 多组织、纯 allow-list ACL、OIDC Code + PKCE、本地事务 + outbox、不可变 index profile。若改变这些默认值，需要新的 ADR 与数据/API 影响评审。

进入实现前仍需产品/安全/运维负责人确定：

1. 首批实际交付形态和责任边界，以及 SaaS 区域/私有化离线约束。
2. 首批连接器优先级；候选为“文件/对象存储 + SharePoint/OneDrive + Confluence”。
3. 行业数据分类级别、外部模型允许清单、默认保留期和法律保全审批人。
4. 登录、授权、同步、ACL/删除传播、检索和问答的 SLO，以及各类数据的 RPO/RTO。
5. 首批 IdP 是否需要独立的安全组/嵌套组语义；若需要，不将其强行等同部门树。
