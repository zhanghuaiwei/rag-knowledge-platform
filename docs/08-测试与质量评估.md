## 3. 集成测试计划

**真实依赖**：PG16、Redis 7.2、MinIO、Milvus（Testcontainers 或本地 Compose）；LLM 用**录制响应**（`VCR`/录制的 SSE 文本），不消耗 API。

| 场景 | 验证点 |
|------|--------|
| 上传→解析→READY | 分片合并、MinIO 对象、document/parse_task 状态推进、Milvus 向量存在 |
| 问答 SSE | `meta→token→final` 事件顺序、`seq` 递增、引用 sources 正确、`answerStatus` 判定 |
| 模型 fallback | 停 Ollama → 自动切云端（mock 云端），cost_record 记 `route_source=cloud` |
| 多租户 | 跨租户请求被插件过滤（返回空/404） |
| Seata | 模拟知识库创建时成员写失败 → 全局回滚，kb 无残留 |
| 分片幂等 | 重复 uploadPart/complete 不产生重复文档与重复向量 |
| 全文搜索 | 关键词命中、`<mark>` 高亮、类型/日期过滤、分页、ACL 白名单过滤（F2.9） |

| 组织 | 部门树 CRUD、用户归属、SSO 配置占位（F2.12） |

## 4. E2E 测试计划

关键路径（Playwright 驱动 web → server → engine → 中间件）：

1. 注册/登录 → 创建知识库 → 上传 PDF → 等待解析 READY（含扫描件 OCR 路径）。
2. 发起问答 → 校验流式渲染与引用跳转 → 反馈（赞/踩）。
3. `/search` 全文搜索 → 高亮片段 → 点击跳转预览定位到页。
4. 审核库：上传 → 待审 → 通过后检索命中；驳回 → 不可检索。
5. 文档 ACL：对某用户设禁止 → 该用户搜索不到、预览 403。
6. 管理后台查看统计与导出 CSV；组织部门树 CRUD。
7. 断网续传分片 → 补传成功。
8. 越权路径：VIEWER 上传 → 403；API Key 超频 → 429。

## 5. RAGAS 质量评估

### 5.1 评估数据集设计（黄金问答集）

| 字段 | 类型 | 说明 |
|------|------|------|
| query | string | 用户问题 |
| reference_answer | string | 期望回答 |
| expected_context | list[string] | 期望召回的相关文档/切片（document_id + chunk_id） |
| domain | enum | 覆盖领域（后端规范/产品手册/安全制度/通用） |
| difficulty | enum | easy / medium / hard |

- **样本量**：首版 ≥ 100 条（每领域 ≥ 20）；随迭代扩到 300 条。
- 来源：真实问答日志采样 + 领域专家标注 + 文档要点人工构造。
- 存储：`ragkb-eval/dataset.jsonl`（与代码仓库分离，避免污染生产数据）。

### 5.2 指标定义与阈值

| 指标 | 定义 | 目标 |
|------|------|------|
| Faithfulness | 回答语句有多少可从检索上下文推导（防幻觉） | ≥ 0.85 |
| Answer Relevancy | 回答与问题的相关性 | ≥ 0.80 |
| Context Precision | 检索结果中相关内容占比 | ≥ 0.70 |
| Context Recall | 期望上下文被召回的比例 | ≥ 0.75 |

> 评估实现：`ragas` 库（`pip install ragas`），用云端 LLM 作为 judge；离线跑批，结果落 `ragkb-eval/results/{date}.json`。

### 5.3 评估流程

```
数据集冻结 → 跑批评估（检索+生成全链路） → 指标落库
  → 对比基线（上次结果） → 恶化则告警 → 调整参数/提示词重跑
```

- 每次知识库配置变更（chunk_size/top_k/reranker）触发一次离线评估。
- CI 门禁：`Faithfulness < 0.85` 或 `Context Recall < 0.75` 时阻断合并（评估用预置测试知识库）。

### 5.4 参数实验矩阵

| 实验 | 变化维度 | 关注指标 |
|------|----------|----------|
| chunk_size | 256 / 512 / 1024 | Context Recall + 语义完整性 |
| chunk_overlap | 0 / 50 / 100 | 召回连续性 |
| top_k | 3 / 5 / 10 | Answer Relevancy + 延迟 |
| reranker 开关 | on / off | Faithfulness + P99 |
| embedding 模型 | bge-m3 vs text-embedding-3 | 精度/延迟对比 |

每个实验记录：指标表 + token 成本 + 延迟，输出实验报告。

## 7. 安全测试

| 类别 | 用例 |
|------|------|
| 越权 | VIEWER 上传/删除 403；跨租户访问 404；跨库成员访问 403 |
| 文档级越权 | 无 ACL view 权限预览 → 403（E-2103）；未发布文档检索 → E-2102 |
| 审核越权 | 非审核人操作审核接口 → 403；REJECTED 二次提交 → E-2202 |
| 注入 | 文件名/检索词 SQL 注入与 XSS 被拒绝或转义；`<mark>` 高亮转义防 XSS |
| 认证 | token 过期/篡改签名 → 401；refresh 复用 → 401 |
| 密钥扫描 | 仓库无硬编码密钥（含 OCR AK/SK，CI 门禁：`gitleaks`/`git grep`） |
| 限流 | 登录 10 次/5min → 429；API Key 超频 → 429 |
| 上传安全 | 伪造扩展名被 Tika 拒绝；ZIP 炸弹限制大小与层级 |
