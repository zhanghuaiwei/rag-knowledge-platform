## 2. 本地开发环境（Docker Compose）

**服务拓扑**：见 `06§1`。`deploy/compose/docker-compose.yml` 关键服务：

```yaml
services:
  postgres:   { image: postgres:16, environment: [POSTGRES_PASSWORD=***], volumes: [pgdata:/var/lib/postgresql/data] }
  redis:      { image: redis:7.2 }
  milvus:     { image: milvusdb/milvus:v2.4.0, depends_on: [etcd, minio] }
  etcd:       { image: quay.io/coreos/etcd:v3.5 }
  minio:      { image: minio/minio:latest }
  ollama:     { image: ollama/ollama:0.3, volumes: [ollama:/root/.ollama] }
  rag-engine: { build: ../rag-engine, depends_on: [milvus, ollama], ports: ["8000:8000"] }
  server:     { build: ../server, depends_on: [postgres, redis, minio, rag-engine], ports: ["8080:8080"] }
  web:        { build: ../web, depends_on: [server], ports: ["3000:3000"] }
```

**环境变量表（server）**：

| 变量 | 说明 |
|------|------|
| `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` | PostgreSQL 连接 |
| `REDIS_URL` | Redis |
| `MINIO_ENDPOINT` / `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | MinIO |
| `RAG_ENGINE_URL` | rag-engine 内部地址 |
| `OAUTH_JWT_PRIVATE_KEY` / `OAUTH_JWT_PUBLIC_KEY` | RS256 密钥对 |
| `DASHSCOPE_API_KEY` / `DEEPSEEK_API_KEY` | 云端模型 |
| `SEATA_SERVER_ADDR` | Seata TC 地址 |

**启动顺序**（2G 实例最小集，见 `deploy/compose/docker-compose.yml`）：

```bash
# 快捷方式：一键完成「校验结构 → 生成 .env → 启动 → 校验数据库初始化」
cd deploy/compose && ./deploy.sh

# 或手工分步：
# 1. 启动中间件（PostgreSQL/Redis/MinIO；凭证取自 deploy/compose/.env）
cd deploy/compose
cp .env.example .env          # 填入真实密码（含 RAGKB_APP_PASSWORD / RAGKB_MIGRATOR_PASSWORD，.env 不提交仓库）
docker compose up -d
# 数据库初始化由 compose 自动完成：PostgreSQL 首次启动（pgdata 卷为空）时执行
# ../ddl/init.sql（角色 + ragkb 库 + 48 表 + 最小种子），密码经 .env 注入。
# 重建：docker compose down -v 后重新 up；独立/托管 PostgreSQL 手动初始化见 04§9。

# 2. 启动应用（骨架阶段可选）
docker compose up -d rag-engine server web
curl http://127.0.0.1:8080/actuator/health
curl http://127.0.0.1:8000/api/engine/health
```

> 阿里云轻量服务器部署：PostgreSQL 为自管实例时同样按上述单文件 `init.sql` 初始化（已内置建库/建角色/建表/种子逻辑）；应用连接使用 `ragkb_app`，迁移使用 `ragkb_migrator`，账号/密码与 `DB_USERNAME`/`DB_PASSWORD` 保持一致。v0.2 模型走云端 API，不在 2G 实例上跑 Ollama/Milvus。

### 2.1 公网暴露中间件（可选）

默认中间件仅绑定 `127.0.0.1`（安全姿态）。需要本机 Navicat / 工具直连公网时：

1. 在 `deploy/compose/.env` 加一行 `MIDDLEWARE_BIND_ADDRESS=0.0.0.0`（回退：删除该行即可恢复仅本机监听）。
2. 阿里云安全组放行 `TCP 5432 / 6379 / 9000 / 9001` —— **强烈建议每项源 IP 只放行你的本机 IP**，勿用 `0.0.0.0/0`。
3. 重新 `./deploy.sh` 或 `docker compose up -d`（compose 检测配置变更自动重建；pgdata 卷保留，数据库初始化不重跑）。

安全约束（已内置，不可关）：
- Redis 强制 `requirepass`（密码取 `.env` 的 `REDIS_PASSWORD`，`deploy.sh` 自动生成）；后端接入 Redis 时连接串必须带该密码。
- Postgres / MinIO 保持密码认证；`MINIO_ROOT_USER` 建议改掉默认 `minioadmin`。
- 公网口令为明文传输，仅建议开发期直连；生产走反向代理 / SSH 隧道。

## 3. K8s 部署（Helm，F2.8）

**Chart 目录**：

```
deploy/charts/ragkb/
├── Chart.yaml
├── values.yaml          # 默认值
├── values.dev.yaml      # dev 覆盖
├── values.prod.yaml     # prod 覆盖
└── templates/
    ├── server-deploy.yaml / server-svc.yaml / server-hpa.yaml
    ├── engine-deploy.yaml / engine-svc.yaml
    ├── web-deploy.yaml / web-svc.yaml
    ├── pg-statefulset.yaml / redis-deploy.yaml / milvus-values.yaml
    ├── ollama-daemonset.yaml
    └── secrets.yaml / configmap.yaml
```

**values.yaml 关键项**：

```yaml
server:
  replicas: 2
  image: harbor.local/ragkb/server:0.1.0
  resources: { requests: { cpu: 500m, memory: 1Gi }, limits: { cpu: "2", memory: 2Gi } }
  probes: { liveness: /actuator/health, readiness: /actuator/health }
engine:
  replicas: 2
  image: harbor.local/ragkb/rag-engine:0.1.0
  nodeSelector: { ollama: "true" }        # 与 Ollama 同节点
ollama:
  modelVol: ollama-pvc
```

**HPA**：

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata: { name: server-hpa }
spec:
  scaleTargetRef: { apiVersion: apps/v1, kind: Deployment, name: server }
  minReplicas: 2
  maxReplicas: 6
  metrics:
    - type: Resource
      resource: { name: cpu, target: { type: Utilization, averageUtilization: 70 } }
```

**回滚**：`helm rollback ragkb <revision>`；Git 仓库作为唯一真相（镜像 tag 版本化）。

## 5. 日志采集

**方案 A（ELK）**：Filebeat DaemonSet → Elasticsearch → Kibana。
**方案 B（PLG 降本）**：Promtail DaemonSet → Loki → Grafana。

**查询示例（Loki LogQL）**：

## 7. JVM 运维手册（F2.7）

### 7.1 堆与 G1 GC 启动参数

```bash
java -Xmx2g -Xms1g \
  -XX:+UseG1GC -XX:MaxGCPauseMillis=200 \
  -XX:InitiatingHeapOccupancyPercent=45 \
  -Xlog:gc*:file=/logs/gc-%t.log:time,uptime:filecount=5,filesize=20m \
  -javaagent:/opt/jmx_prometheus_javaagent.jar=9404:/opt/jmx_exporter_config.yml \
  -jar ragkb-server.jar
```

- 大文档解析 OOM → 先查堆 Dump（见 7.3），确认是否 `-Xmx` 不足还是对象泄漏。
- G1 暂停 > 200ms → 看 GC 日志，调整 IHOP / 减小 Humongous 分配。

### 7.2 线程池监控与排查

- 指标：`ragkb_pool_active / ragkb_pool_queue_size / ragkb_pool_completed`（解析/上传/审计池）。
- `queue.size()` 持续增长 → 消费慢，检查 rag-engine 延迟。
- CallerRunsPolicy 生效 → 池满且队列满，请求线程代跑；需评估扩池还是削峰。

### 7.3 jmap / MAT 堆 Dump

```bash
jps -l                          # 找 PID
jmap -dump:live,format=b,file=heap.bin <pid>
# 下载 heap.bin → MAT：Dominator Tree 找最大对象 → Leak Suspects Report
# OQL：SELECT * FROM com.ragkb.document.entity.DocumentEntity   # 按类查实例
```

### 7.4 Arthas 诊断

```bash
curl -O https://arthas.aliyun.com/arthas-boot.jar && java -jar arthas-boot.jar
# dashboard                 # 实时 CPU/内存/GC/线程
# thread -n 3               # CPU 最高 3 线程
# watch com.ragkb.document.service.ParseOrchestrator onParseResult '{params,returnObj}' -x 2
# trace com.ragkb.pipeline.RagEngineClient queryChat '#cost>500'
# jad --source-only com.ragkb.auth.service.TokenService
```

## 8. 回滚与故障演练

| 场景 | 演练步骤 | 目标 |
|------|----------|------|
| Ollama 故障 | 停 Ollama → 验证问答自动 fallback 云端 → 恢复 Ollama → 路由回到本地 | 业务不中断 |
| 服务版本回滚 | `helm rollback` 上一个镜像 tag → 验证健康 | 恢复 < 5min |
| 数据库恢复 | 从备份恢复 PG → 校验 usage_daily 与 document 一致性 | 数据不丢 |
| Milvus 重建 | 导出向量 → 重建 Collection → 重放解析（幂等） | 索引可重建 |

**备份策略**：PG 每日 pg_dump + WAL 归档；MinIO bucket 版本控制；Milvus 定期导出向量快照。
