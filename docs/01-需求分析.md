## 1. 背景与目标

### 1.1 建设背景与目标定位

企业在运营中沉淀了大量非结构化文档（制度规范、技术文档、产品手册、项目纪要），普遍存在三大痛点：

| 痛点 | 现状 | 影响 |
|------|------|------|
| 检索效率低 | 依赖人工翻阅与文件夹检索 | 知识查找耗时，重复劳动 |
| 知识流失 | 文档分散于各系统，缺乏统一管理 | 经验难以沉淀与复用 |
| 信息口径不一 | 同主题多版本文档并存 | 决策依据不一致，沟通成本高 |

本系统定位为**企业级通用知识库平台**：以「知识库管理 + 多格式文档解析 + 语义检索 + 可信问答」为核心，为组织提供知识沉淀 → 语义检索 → 引用可信问答的完整闭环。系统面向企业内部与 SaaS 两类交付形态设计，支持多租户数据隔离、私有化/容器化部署、模型路由降本，并配套管理后台与用量运营能力。

### 1.2 业务目标

1. **知识沉淀**：企业内部文档（制度、技术规范、产品手册）集中管理，支持多格式上传与多租户隔离。
2. **智能问答**：基于文档内容的自然语言多轮问答，答案带原文引用，降低检索门槛。
3. **可运营**：管理后台提供用量统计、Token 成本、知识库健康度，指导内容与模型优化。

### 1.3 技术目标

- 构建完整的 RAG 全流程（切分 → 向量化 → 检索 → 注入 → 生成），并为每个环节建立失败应对机制（重试、降级、幂等）。
- 落地混合检索（向量 + BM25 + 融合 + 精排）与模型路由（本地/云端、自动 Fallback）的工程级检索系统。
- 以 Seata AT 模式保证跨服务数据一致性，以 MyBatis-Plus 插件体系统一处理多租户、乐观锁、敏感字段等横切问题。
- 完成 K8s 生产级部署、全链路监控与 JVM 运维能力建设。

### 3.3 多租户隔离策略

- 以 `tenant_id` 列实现数据行级隔离；MyBatis-Plus `TenantLineInnerInterceptor` 自动追加 `WHERE tenant_id = ?`。
- 租户 ID 从 JWT claim `tenant_id` 提取，注入 `TenantLineHandler`。
- 全局表（`sys_user`、`audit_log`、`cost_record`）按场景豁免或按租户过滤，规则见 `04-数据库设计§5`。
- **禁止跨租户查询**：代码层 + 插件双重保证，admin 查询需显式指定租户范围。

## 4. 功能需求

> 每项格式：描述 / 用例步骤 / 业务规则 / 验收标准。

### 4.1 F2.1 多知识库管理

**描述**：用户可创建、编辑、删除知识库，配置解析参数与检索参数；知识库可绑定成员、克隆、切换。

**用例步骤**：
1. 创建知识库：填写名称、描述、可见性（私有/公开）、检索配置（`embedding_model`、`chunk_size`、`chunk_overlap`、`top_k`）。
2. 成员管理：邀请/移除成员并分配角色。
3. 知识库切换：问答页选择目标知识库（多选）。
4. 克隆：复制配置与文档到新知识库（异步）。

**业务规则**：
- 知识库名称唯一（租户内）；删除为软删除（`is_deleted=1`）。
- 克隆时新知识库的 `tenant_id` 继承源库；文档向量复制为深拷贝。
- 问答至少选择一个知识库，最多同时选择 5 个。

**验收标准**：
- [ ] 创建后出现在列表，编辑/软删除生效。
- [ ] 成员角色变更即时生效，VIEWER 无法上传文档（接口 403）。
- [ ] 克隆完成前目标库状态为 `CLONING`，完成后可正常问答。

---

### 4.2 F2.2 文档全生命周期管理

#### 4.2.1 多格式上传

**描述**：支持 PDF / Word(.docx) / Markdown / TXT，拖拽或点击上传，非法格式拒绝。

**业务规则**：允许格式 `pdf | docx | md | markdown | txt`；单文件 ≤ 50MB（>10MB 走分片，见 4.2.2）；文件名长度 ≤ 128。

**验收**：[ ] 上传成功显示解析进度；[ ] 上传 `.doc`/`.exe` 等拒绝并提示（基于 Apache Tika Magic Number 检测）。

#### 4.2.2 分片上传与断点续传

**描述**：>10MB 文件前端分片（每片 5MB）上传，显示进度条，支持断点续传与秒传。

**用例步骤**：
1. 前端 `POST /api/documents/upload/init` 获取 `uploadId` 与已上传分片列表（秒传判断）。
2. 逐片 `PUT /api/documents/upload/{uploadId}/parts/{partNumber}`。
3. 全部完成后 `POST /api/documents/upload/{uploadId}/complete` 触发合并与解析。

**业务规则**：分片元数据存 Redis（TTL 24h）；分片幂等（相同 partNumber 重复上传覆盖）；合并后删除 Redis 元数据并写入 MinIO。

**验收**：[ ] 断网重传只补传缺失分片；[ ] 秒传（同指纹）跳过已存在分片；[ ] 24h 未完成自动过期清理。

#### 4.2.3 格式自动检测

**描述**：基于文件头（Magic Number）+ MIME 识别真实格式，忽略扩展名。

**业务规则**：Apache Tika `detect(InputStream)` 判定；非法或与声明的扩展名严重不符时拒绝。

**验收**：[ ] 将 `.txt` 改名 `.pdf` 后上传被拒绝；[ ] 识别 PDF 版本兼容性。

#### 4.2.4 解析状态机

**描述**：文档解析状态流转：`UPLOADING → PARSING → SPLITTING → EMBEDDING → READY / FAILED`。

**业务规则**：状态迁移由 `parse_task` 记录推进；任一环节失败 → `FAILED` 并记录 `error_msg`；`READY` 表示向量已入库且可检索。

**验收**：[ ] 前端状态随进度实时刷新；[ ] 非法迁移被拒绝（如 READY→UPLOADING）。

#### 4.2.5 解析失败重试

**描述**：失败文档支持手动重试，最多重试 3 次。

**业务规则**：重试重置 `retry_count+1`；超过 3 次锁定需管理员介入；重试前清理已入库的部分向量（幂等补偿）。

**验收**：[ ] 重试成功进入正常流程；[ ] 超过 3 次返回明确提示且无法继续重试。

#### 4.2.6 文档版本管理

**描述**：同名文档重新上传保留历史版本，可回滚。

**业务规则**：`document_version` 表保存历史镜像（MinIO 路径 + 元数据）；回滚将当前版本标记为指定历史版本，重新触发解析；最新版本参与检索。

**验收**：[ ] 版本列表按时间倒序展示；[ ] 回滚后问答引用最新版本内容。

#### 4.2.7 ZIP 批量导入

**描述**：上传 ZIP 自动解压导入全部文档（支持目录层级）。

**业务规则**：ZIP ≤ 200MB；内部文件逐个进入解析队列；单个文件失败不影响其余；目录名作为文档分组标签（Metadata 前缀）。

**验收**：[ ] 批量导入进度可追踪；[ ] 单文件失败可定位且不阻塞整体。

### 4.3 F2.3 智能问答引擎

**描述**：基于选中知识库的多轮对话问答，SSE 流式输出，答案带原文引用与置信度，支持追问建议与用户反馈。

**用例步骤**：
1. 用户在 `/chat` 选择知识库 → 输入问题 → 创建/复用会话。
2. server 转发到 rag-engine `POST /api/query/chat` → 混合检索 → 精排 → LLM 生成 → SSE 流式返回。
3. 前端逐 token 渲染；回答结尾附引用（文档名 + 页码/段落），可点击查看原文。
4. 用户可点赞/踩，踩时填写原因。

**业务规则**：
- 检索阈值：融合后最高分 < 阈值（默认 0.55）或 Reranker 得分低于阈值时，回复「根据已有资料无法确定，建议查阅原文」。
- 多轮上下文：会话级 `ChatMemory`，最多保留最近 10 轮。
- 引用格式 `[文档名-页码]`，`sources_json` 落库。
- 追问建议：每次回答后生成 3 条候选追问（可关闭）。

**验收标准**：
- [ ] SSE 逐 token 输出流畅，断连可重连。
- [ ] 引用可点击跳转并高亮原文段落。
- [ ] 超阈值时明确回复"无法确定"而非臆造。
- [ ] 多轮追问能结合上文回答。

### 4.4 F2.4 模型路由与降级

**描述**：Embedding 与 LLM 均支持本地/云端路由与自动降级，并记录成本。

**业务规则**（详见 `03-详细设计§7` 路由规则表）：
- Embedding：默认 Ollama BGE-M3（本地免费）；月度问答 >1000 次的知识库可配置切换云端 `text-embedding-3-large`。
- LLM：短文本（<500 tokens）→ DeepSeek v3（性价比）；长文本/复杂推理 → 通义千问-long；默认 → Qwen2.5-7B（本地）。
- Fallback 触发：Ollama 超时 >10s / OOM / HTTP 5xx / 429 → 自动切云端重试（最多 1 次）。
- 每次调用记录 `cost_record`（模型/token/费用）。

**验收标准**：
- [ ] 停止本地 Ollama 后，问答自动切云端成功。
- [ ] `model_route_config` 修改规则即时生效。
- [ ] 成本记录与账单可核对。

### 4.5 F2.5 用量统计与分析

**描述**：管理后台展示问答量、Token 消耗与费用、热门文档、用户活跃度、知识库健康度，支持导出。

**统计口径**（详细见 `03-详细设计§2.5`）：
- 问答量：按日/周/月聚合 `usage_daily.qa_count`。
- Token 与费用：按模型维度聚合 `cost_record`，单价表见 `04`。
- 热门文档 Top10：按引用次数倒序。
- DAU：当日去重 `user_id` 数。
- 健康度：无答案率（`no_answer_count / qa_count`）、低置信率（`low_conf_count / qa_count`）。

**验收标准**：
- [ ] 图表可按日/周/月切换。
- [ ] 报表可导出 CSV/Excel（EasyExcel）。
- [ ] 健康度趋势可指导知识库优化。

### 4.6 F2.6 OAuth2 安全架构

**描述**：密码模式获取 Token；资源服务器校验 JWT；方法级鉴权；API Key 支持外部调用；操作审计。

**用例步骤**：
1. 用户名+密码 → `POST /oauth2/token`（password grant）→ accessToken + refreshToken。
2. 前端携带 Bearer token 访问受保护资源；过期用 refreshToken 轮换。
3. 外部系统用 API Key（Bearer 前缀 `ApiKey`）调用问答接口。
4. 所有写操作记录审计日志。

**业务规则**：
- accessToken TTL 2h；refreshToken TTL 7d，一次性轮换，Redis 记录黑名单。
- API Key 仅存 SHA-256 `key_hash`；支持过期时间与调用频率限制。
- `@AuditLog` 注解方法级埋点，异步落库。

**验收标准**：
- [ ] 未带 token / 过期 token 返回 401；无权限返回 403。
- [ ] API Key 泄露可吊销；超频返回 429。
- [ ] 审计日志含操作者/资源/结果/时间/IP/requestId。

### 4.7 F2.7 JVM 深度调优（运维性需求）

**描述**：保证大文档处理与批量导入场景下 JVM 稳定，并具备线上诊断能力。

**指标与验收**（详见 `09-部署运维指南§7`）：

| 调优点 | 目标场景 | 验收标准 |
|--------|----------|----------|
| 堆内存 | 上传 50MB PDF 解析 | 无 OOM；`-Xmx2g` |
| G1 GC | 文档批处理 | GC 暂停 < 200ms；`-XX:MaxGCPauseMillis=200` |
| 线程池 | 批量导入 100 文档 | 不丢任务、无死锁 |
| 堆 Dump | 内存泄漏排查 | jmap + MAT 定位泄漏点 |
| Arthas | 线上 CPU 飙升 | `thread -n 3` / `dashboard` 定位热点 |

### 4.8 F2.8 K8s 部署与监控

**描述**：Spring Boot / FastAPI / PostgreSQL / Redis / Milvus / MinIO / Ollama 全部 K8s 部署，具备探针、日志、指标、告警。

**业务规则**：
- `livenessProbe` / `readinessProbe` 基于 Actuator `/actuator/health`；Ollama 用 `startupProbe` 慢启动保护。
- Filebeat → Elasticsearch → Kibana 收集结构化日志（或 Loki 降本）。
- Prometheus JMX Exporter 采集 JVM；Micrometer 暴露业务指标。
- 告警：错误率 >5%、P99 >3s、磁盘 >85%、探针失败。

**验收标准**：
- [ ] Pod 异常自动重启/移出 Service。
- [ ] Grafana 面板展示 JVM + 问答 QPS/P99/错误率。
- [ ] 告警规则命中后通知到钉钉/Slack。

### 4.9 F2.9 全文搜索

**描述**：独立的文档搜索入口（区别于问答）：关键词搜索、结果列表、命中高亮、按类型/日期/知识库过滤，分页返回；支持通过 API Key 对外开放搜索能力。

**用例步骤**：
1. 用户进入 `/search`，输入关键词（支持多词/布尔 `AND/OR`），选择过滤条件（知识库、文件类型、日期范围）。
2. server 转发 rag-engine `POST /api/query/search`（BM25 为主，可选向量融合）→ 返回命中切片与高亮片段。
3. 结果列表展示：文档名、所属知识库、高亮片段、页码、类型、更新时间；点击跳转文档预览定位到页码。
4. 外部系统可用 API Key 调用同一搜索端点（机器访问）。

**业务规则**：
- 仅检索 `review_status=PUBLISHED` 且 `is_deleted=false` 且 ACL 可见的文档（F2.13/F2.14 联动）。
- 高亮：对命中关键词在片段内加 `<mark>` 标签（服务端 BM25 命中 term 渲染，不额外调模型）。
- 默认排序：BM25 相关性分 + 时间降权；支持按时间/相关性切换。
- 搜索埋点：记录搜索词、命中数、点击结果（供热门词统计，复用 `usage_daily` 体系）。

**验收标准**：
- [ ] 关键词搜索返回带高亮的片段与文档名。
- [ ] 按类型/日期/知识库过滤生效；分页正确。
- [ ] 无权访问的文档不出现在结果中（ACL 过滤）。
- [ ] API Key 可调用搜索端点，返回结构与人机一致。

### 4.10 F2.10 文档在线预览

**描述**：在浏览器内预览 PDF/Word/Markdown/TXT/Excel/PPT 原文；从问答引用或搜索结果可直接跳转定位到对应页码/章节。

**用例步骤**：
1. 文档列表点击「预览」→ 浏览器渲染原文。
2. 从 `/chat` 引用点击「查看原文」→ 打开预览并定位到 `page_no` / `section_title`。
3. 从 `/search` 结果点击 → 定位到命中片段所在页。

**业务规则**：
- 预览走 server 代理文件流（`GET /api/documents/{id}/content`），前端负责渲染：PDF（PDF.js）、DOCX（mammoth → HTML）、MD/TXT（markdown 渲染）、XLSX（SheetJS）、PPTX（转换 PDF 或基础渲染，见 F2.10 详细设计）。
- 大文件预览支持 HTTP Range 分段请求。
- 预览受 ACL `view` 权限控制（F2.14）；下载原文需 `read_original` 权限（或按文档策略）。

**验收标准**：
- [ ] PDF/Word/MD/TXT 在浏览器正常预览。
- [ ] 引用/搜索跳转能定位到指定页。
- [ ] 无 ACL 权限用户预览被拒绝（403）。

### 4.11 F2.11 扫描件 OCR

**描述**：对无文本层的扫描 PDF（及图片型 PDF）自动执行 OCR，纳入正常切片与检索流程。

**业务规则**：
- 解析 Pipeline 中检测：PyMuPDF 提取每页文本，文本量接近 0 的页判定为扫描页 → 走 OCR。
- OCR 采用**阿里云文字识别 API**（与云环境契合，中文/表格识别强）：逐页转图片 → 调 OCR → 重建文本层 → 进入正常切片流程（F2.2）。
- 可配置：知识库 `ocr_enabled` 开关（默认开启）；OCR 凭证走环境变量（`ALIYUN_OCR_ACCESS_KEY_ID/SECRET`，红线不硬编码）。
- OCR 失败降级：整篇标记 FAILED 并给出 OCR 失败原因；支持重试（F2.2 重试链路复用）。
- 混合文档（部分扫描页部分文本页）：仅扫描页走 OCR，其余正常提取。

**验收标准**：
- [ ] 纯扫描 PDF 上传后识别成功并可被问答检索到。
- [ ] OCR 失败时文档 FAILED，错误信息含"OCR 失败"。
- [ ] 关闭 `ocr_enabled` 后扫描件不触发 OCR（走文本提取，无文本则 FAILED）。

### 4.12 F2.12 组织架构与账号体系

**描述**：内建部门树（`sys_org`），用户归属部门；预留 `SsoProvider` 接口用于二期对接 OIDC/LDAP。

**用例步骤**：
1. ADMIN 在 `/admin/orgs` 创建部门树（支持层级），将用户分配到部门。
2. ACL 授权时可选择「按部门授权」：给某部门授权后，该部门所有成员获得相应权限（F2.14）。
3. 二期：启用 SSO 后，用户可通过企业账号登录（本版本仅提供接口与配置占位，见详细设计）。

**业务规则**：
- 部门为树形结构（`parent_id` 自关联），删除部门需先清空成员或迁移。
- 用户 `org_id` 可空（未分配部门的用户）。
- SSO：定义 `SsoProvider` 接口（`authenticate(authCode) → SsoUser`），一期注册本地账号实现，二期注册 OIDC/LDAP 实现；配置 `sso.enabled=false` 占位。

**验收标准**：
- [ ] 部门树增删改查；用户归属部门可设。
- [ ] 按部门授权的 ACL 对部门成员生效。
- [ ] `sso.enabled=false` 时登录走本地密码模式；配置项存在但未启用。

### 4.13 F2.13 内容审核与发布流

**描述**：文档解析完成后按知识库策略进入审核流：待审核 → 通过（发布）/ 驳回；未发布文档不参与检索。

**用例步骤**：
1. 知识库开启 `requires_review` 后，解析成功（READY）的文档自动进入 `PENDING_REVIEW`。
2. 审核人（ADMIN / REVIEWER / 库 OWNER）在 `/admin/reviews` 队列查看待审文档（可预览原文）。
3. 通过 → `PUBLISHED`（开始参与检索）；驳回 → `REJECTED` + 驳回意见，文档可修改后重新提交（回到 PENDING_REVIEW）。
4. 未开启审核的知识库：解析完成直接 `PUBLISHED`（与现状一致）。

**业务规则**：
- 审核记录留痕（`document_review`：审核人/动作/意见/时间），可追溯。
- 检索/搜索/问答仅命中 `PUBLISHED` 文档（F2.9/F2.3 联动，Milvus 标量过滤）。
- 驳回不删除向量（保留，待重审后复用）；重新提交触发重新解析。

**验收标准**：
- [ ] 待审文档不出现在搜索与问答结果中。
- [ ] 通过后立即可检索；驳回后不可检索且保留审核记录。
- [ ] 审核操作权限正确（ADMIN/REVIEWER/OWNER）。

### 4.14 F2.14 文档级权限（ACL）

**描述**：默认文档继承知识库成员权限；可对单篇文档设置 ACL（按用户/部门/角色授权查看），细粒度控制可见性。

**业务规则**：
- `document_acl` 白名单式：文档有 ACL 记录时按记录判定；无记录时继承知识库权限（`kb_member`）。
- 权限点：`view`（可搜索到/可预览）、`read_original`（可下载/查看原文全文）。
- 授权主体：`user`（具体用户）/ `org`（部门，含子部门）/ `role`（系统角色）。
- 影响链路：检索（F2.9/F2.3）仅返回 ACL 可见文档；预览（F2.10）校验 `view`。
- 实现：检索时 server 预取当前用户可见 `document_id` 集合，作为 Milvus 标量过滤条件（文档量放大后可下沉为标量字段，见详细设计）。

**验收标准**：
- [ ] 无 ACL 记录文档按知识库权限判定。
- [ ] 有 ACL 记录时按记录判定（覆盖知识库权限）。
- [ ] 按部门授权对成员生效（含子部门）。
- [ ] 被 ACL 排除的用户搜索不到、预览 403。

## 5. 非功能需求

### 5.1 性能指标

| 场景 | 指标 | 目标 |
|------|------|------|
| 文档上传 | 上传 P95 响应 | < 2s（≤10MB 文件） |
| 解析吞吐 | 单文档 PDF(10MB) 解析至 READY | ≤ 60s |
| 问答 | 首 token 延迟（本地模型） | ≤ 3s |
| 问答 | 完整回答（300 tokens） | ≤ 30s（含检索） |
| 并发 | 在线会话数 | ≥ 100 |
| 检索 | 单次检索 P95 | < 300ms（10 万级向量） |
| 搜索 | 全文搜索 P95 | < 500ms（含过滤 + 高亮） |
| 预览 | 首屏渲染 | PDF 10MB 文件 < 3s |

### 5.2 安全要求

- 认证：OAuth2 password 模式；JWT 签名使用 RS256（Nimbus 验签）。
- 授权：方法级 `@PreAuthorize` + 知识库成员角色 + **文档级 ACL（F2.14）** + 多租户过滤四层。
- 审计：所有写操作记 `audit_log`。
- 数据隔离：`tenant_id` 强制注入；日志与审计不记录明文密码与完整敏感字段（拦截器自动加解密，见 `04§5`）。
- 密钥管理：所有密钥（含 OCR `ALIYUN_OCR_ACCESS_KEY`）走环境变量 / K8s Secret，**绝不硬编码**。

### 5.3 可用性

- 模型层：本地 Ollama 不可用自动 fallback 云端，业务不中断。
- 依赖降级：Milvus 不可用时问答返回明确错误并提示稍后重试；MinIO 不可用时上传失败但不影响已有检索。
- 服务多副本（K8s，副本数 ≥2）。

### 5.4 可观测性

- 统一 `requestId` 跨 Java/Python 传递，贯穿日志/指标/错误响应。
- 指标：JVM、解析任务、问答 QPS/P99/错误率、模型调用成本。
- 日志：结构化 JSON，脱敏后采集。

### 5.5 数据规模预估

| 项 | 预估 |
|----|------|
| 租户数 | ≤ 50 |
| 单租户文档数 | ≤ 2 万 |
| 向量规模 | ≤ 100 万条（chunk 级） |
| 会话/月 | ≤ 10 万次问答 |
| 单文档大小 | ≤ 50MB |

### 6.1 功能验收清单

### 6.2 性能验收
